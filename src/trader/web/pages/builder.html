How it works
  1. Describe the idea in one or two sentences - the signal, when to buy, when to sell. Numbers help ("RSI below 30", "50-day average").
  2. The app writes the strategy and checks it: a test run on real data and a look-ahead check that proves it never uses tomorrow's prices.
  3. Read the rules it shows you - if they are not what you meant, rephrase and try again.
  4. Test it now: a backtest with realistic trading costs, compared with buy-and-hold.
  5. Optimise the numbers out of sample, then forward-test it on paper.
You never have to write or read code - it is there under "Show the code" if you are curious.
The plugin API
class MyStrategy(Strategy):
    name = "My strategy"
    params = {"fast": {"default": 10, "min": 2}, "slow": 30}
    def generate_signals(self, data) -> pd.Series:
        ...  # 1 long, 0 flat, -1 short
  • data is an OHLCV DataFrame (open high low close volume); multi-asset strategies set multi_asset = True and get {symbol: DataFrame}, returning a DataFrame of weights.
  • Use only data up to each bar. The engine trades on the next bar - the look-ahead check proves it.
  • Helpers: trader.core.indicators as ta (sma, ema, rsi, macd, bollinger, atr, donchian…), enter_exit, flat_until_ready, trader.core.ml.
  • Params become an auto-generated form on the Backtest page; read them as self.p.fast.
  • Allowed imports: pandas, numpy, math, statistics, scipy, sklearn and trader.core.*.
Sandbox. Code runs in a separate, isolated Python process with an import allow-list, no file / dunder access, a CPU-time and memory limit and no API keys in its environment. It is designed for local, trusted use - do not run other people's code on a shared server.
